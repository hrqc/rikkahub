# V1 M2.2 聊天内手机操作

在聊天框输入当前要做的事。普通计算、知识问题和操作方法直接回答；明确要求操作某个应用时，当前模型可调用无副作用的 `request_phone_control` 提议。目标含糊或本机存在同名应用时，聊天显示一次目标确认卡。

## 执行流程

1. 仅新的本地聊天输入创建一次意图绑定，包含会话、助手、消息 ID、随机代次和用户原文。模型不能自行提供授权。
2. 提议先暂存，原模型生成成功结束后才发布。与其他工具同批时，成功提议后其他调用明确未执行，本轮结束。
3. 本地解析允许的目标应用。只有明确操作表达、唯一名称匹配且用户原文提及该目标时自动开始；其余交给聊天确认卡。应用清单只在本机使用。
4. 消费提议一次，等待聊天空闲，建立单目标授权。Root 和截图默认关闭。执行使用用户原文，不使用模型摘要替换用户任务。
5. 本地打开目标一次，等待系统窗口就绪后才提交控机续轮。系统启动许可仍需人确认。控机模型先观察当前页面，再通过现有受限工具执行。
6. 聊天卡显示准备、运行、暂停、结束状态，提供暂停、继续和 STOP。模型本轮结束即撤销匹配授权；暂停需用户手动恢复。

## 生命周期与授权

- 普通发送、语音、编辑、重生成均使旧意图与手机授权失效。旧历史消息、Web 普通请求以及审批恢复不会自动继承 phone tools。
- 高级面板与聊天续轮都必须显式携带当前 token；创建任务、保存消息和发送请求时再次核对。没有有效 token 不下发低层控机工具。
- 离开聊天或更换助手会撤销尚未发布、已消费但未启动、以及正在运行的任务。旧页面迟到销毁不能撤销新页面的任务。
- 旧 Job、重复确认、过期工具名与迟到取消不能启动或撤销其他任务。原有观察/动作预算、目标窗口限制及敏感页保护继续生效。

## USB 测试输入

`scripts/mobile-agent/build-input-driver.ps1` 使用已安装 JDK 和 Android SDK 离线构建一个独立测试 APK。它无网络权限，无桌面启动入口，仅供 `adb shell am instrument` 调用。驱动使用不抑制现有无障碍服务的 UiAutomation，向主 debug 应用中已聚焦、空白、非密码输入框写入最长 2000 字符并核对结果。另提供仅限合成测试应用的有界页面文字观察，用于 USB 断言点击计数和精确输入；不读取私人应用内容，不修改系统权限。

测试包单独安装为 `me.rerere.rikkahub.debug.inputdriver`，与正常 AndroidJUnit 测试包分离。还可尝试点击已经可见、标题与合成应用目标均匹配的通知 STOP，找不到时明确失败，不选择其他通知。ColorOS 折叠通知可能需要先展开。驱动源代码和构建脚本纳入仓库，APK、签名文件与设备原始记录保留在本地项目目录。

## 验收边界

本地规则只承担保守授权判断，语义理解依赖当前模型。复杂、含糊、引用或否定表达可能要求确认。系统许可弹窗和锁屏仍需要人处理。具体测试结果记录在模型测试报告中；本功能不代表整个 V1 或 OPPO 非 Root 机已验收。
