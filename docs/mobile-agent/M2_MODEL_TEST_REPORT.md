# V1 M2.1 / M2.2 真实模型测试记录

2026-09-26，用户已在 APP 中配置 API 并授权实机测试。设备为一加 Ace 5 Pro（Android 16），模型为用户配置的 `deepseek-flash`。只操作无网络权限的合成测试应用，Root 与截图均关闭，不读取或输出 API 密钥。V2 未修改。

## 修复及回归

- 无障碍服务中断、断连、重绑分别记录真实原因，不再统一误报“用户从通知停止”。
- 新授权通过系统提示明确当前工具名；旧工具名继续拒绝执行，但返回当前可用工具名，不能重绑旧调用。
- 控机任务要求模型启用工具调用能力。
- 本地打开目标一次，最多等待 60 秒，窗口就绪后才发送模型请求。系统启动确认交给用户，等待期间不读确认页、不重复打开。超时、停止、锁屏、断连均不继续发送。
- 首次准备阶段尚未发送的原始任务可在用户手动恢复后继续；旧准备协程不得取消新授权。
- 80 项选定 JVM 回归通过，0 失败、错误、跳过；主 APK 与仪器测试 APK 构建通过。版本 192 / `2.5.4-mobile-agent-v1-m2.1`。

## 真实模型证据

第一条通过任务：在 APP 面板选择 Mobile Agent Test Fixture，让模型读取页面、单击“点击测试”、核对计数。APP 本地启动目标后，测试人员只处理 ColorOS 的“仅本次允许”；没有代替模型点击测试按钮。

- 模型读取初始计数 0，调用本次授权的 `phone_*_click`，工具后置观察返回计数 1。
- 独立截图显示实际点击次数 1，模型最终回答与页面一致。
- 完成后由测试人员 STOP，撤销授权。
- 本地证据位于项目根 `artifacts/v1-m2/model-tests/oneplus-20260926/34-v192-ready.png`、`35-v192-result.png`、`36-v192-chat.png`。原始设备记录不上传仓库。

旧版首测出现系统确认未结束就重复 open_app、前台保护暂停；同一聊天重新授权后模型使用旧工具名也失败。另有一次准备指令未实际提交，不计作模型用例。以上均不计通过。运行模型期间不使用会干扰本应用无障碍服务的 UIAutomator。

第二条面板任务复用了同一聊天并重新授权：模型第一次沿用旧工具名，被本地拒绝后，根据返回的当前工具名重新观察，随后输入中文、进入第二页并返回。页面与聊天记录吻合。但 USB `input text` 经搜狗输入法将指令末尾的 `192` 改成了 `Chinese9Cheese`，模型实际收到和填入的均为该改写内容。因此这次只证明多步操作和过期工具恢复，不计作 `中文测试192` 精确输入用例。后续改用测试 APK 的精确文本驱动。
