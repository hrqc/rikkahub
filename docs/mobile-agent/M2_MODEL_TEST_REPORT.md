# V1 M2.1–M2.5 模型与回归测试记录

2026-09-26，用户已在 APP 中配置 API 并授权实机测试。设备为一加 Ace 5 Pro（Android 16），模型为用户配置的 `deepseek-flash`。M2.1/M2.2 操作无网络权限的合成测试应用；后续另经用户授权测试微信文件传输助手。控机 Root 与截图均关闭，不读取或输出 API 密钥。V2 未修改。

## 修复及回归

- 无障碍服务中断、断连、重绑分别记录真实原因，不再统一误报“用户从通知停止”。
- 新授权通过系统提示明确当前工具名；旧工具名继续拒绝执行，但返回当前可用工具名，不能重绑旧调用。
- 控机任务要求模型启用工具调用能力。
- 本地打开目标一次，最多等待 60 秒，窗口就绪后才发送模型请求。系统启动确认交给用户，等待期间不读确认页、不重复打开。超时、停止、锁屏、断连均不继续发送。
- 首次准备阶段尚未发送的原始任务可在用户手动恢复后继续；旧准备协程不得取消新授权。
- 80 项选定 JVM 回归通过，0 失败、错误、跳过；主 APK 与仪器测试 APK 构建通过。版本 192 / `2.5.4-mobile-agent-v1-m2.1`。

## 真实模型证据

第一条通过任务：在 APP 面板选择 Mobile Agent Test Fixture，让模型读取页面、单击“点击测试”、核对计数。APP 本地启动目标后，测试人员只处理 ColorOS 的“仅本次允许”；没有代替模型点击测试按钮。

- 模型读取初始计数 0，调用本次授权的 `phone_*_click`，工具后置观察返回计数 1。
- 独立截图显示实际点击次数 1，模型最终回答与页面一致。
- 完成后由测试人员 STOP，撤销授权。
- 本地证据位于项目根 `artifacts/v1-m2/model-tests/oneplus-20260926/34-v192-ready.png`、`35-v192-result.png`、`36-v192-chat.png`。原始设备记录不上传仓库。

旧版首测出现系统确认未结束就重复 open_app、前台保护暂停；同一聊天重新授权后模型使用旧工具名也失败。另有一次准备指令未实际提交，不计作模型用例。以上均不计通过。运行模型期间不使用会干扰本应用无障碍服务的 UIAutomator。

第二条面板任务复用了同一聊天并重新授权：模型第一次沿用旧工具名，被本地拒绝后，根据返回的当前工具名重新观察，随后输入中文、进入第二页并返回。页面与聊天记录吻合。但 USB `input text` 经搜狗输入法将指令末尾的 `192` 改成了 `Chinese9Cheese`，模型实际收到和填入的均为该改写内容。因此这次只证明多步操作和过期工具恢复，不计作 `中文测试192` 精确输入用例。后续改用测试 APK 的精确文本驱动。

### M2.3 用户实际失败（版本 194）

194 为本地中间修复版，补充了若干发送/重试句式与过期工具恢复提示，155 项选定 JVM 回归通过，但没有解决语义分类依赖关键词的问题，不设稳定里程碑。

- APP 对用户实际输入“帮我给微信助手发送测试信息”调用了 `request_phone_control`，返回 `phone_intent_rejected` / `execution_started=false`。ADB 确认无障碍服务绑定、无崩溃，安装版本为 194。
- 使用该构建的真实 JVM 类复核：原句及把对象补全成“文件传输助手”的同类句子都被分类为 `INFORMATIONAL`。规则只识别“发送信息”等紧邻表达，漏掉了中间带“测试”的句子。
- 文件传输助手的独立只读断言未取得通过证据。前期一次启动被微信双开选择阻挡直至超时；后续提议/重试进入过控机续轮，但没有核实实际发送，不能记为微信任务成功。
- 用户随后选择亲自操作手机，Codex 只读监控。本地证据 68、69 记录错误回复及工具返回，不上传原始图片或设备数据。

### M2.4 语义路由修复（版本 195）

本次移除工具、提议 Store 与协调器的语义硬拒绝。模型在既有聊天请求中理解口语、错字和上下文，未知句式可以提出任务。本地仅校验原文绑定、参数、时效与一次性消费；自动开始范围收窄为准确命名应用的简单打开请求，其余需聊天确认。确认卡展示模型理解及可展开的完整原文，执行始终保留用户原文。

最终提示与代码的 161 项选定 JVM 回归通过，0 失败、错误、跳过。主 APK 与 AndroidJUnit 测试 APK 构建、签名核验通过。主包以 `install -r` 覆盖安装到一加，确认 versionCode 195；未清除 API 或聊天数据。更新后即时检查无障碍尚未绑定、无崩溃，交由用户打开 APP 后核对连接并继续实测。本轮未调用真实模型 API，也未代用户操作微信。

回归覆盖实际失败原句、错字、上下文省略、重试、消息正文问号，以及模型误提议问题/否定/引用时无 token、无打开、无页面读取；确认后核对原文、选定应用和一次性启动。普通问答是否被模型准确识别、错别字是否被正确解释以及微信实际发送，仍由用户实机复测，单元测试不作为这些真实模型结果。

建议人工顺序：普通方法问题应直接回答；“帮我给微信助手发送测试信息”应进入理解确认或必要澄清；补充“就是文件传输助手，只发一次”后再核对目标与实际消息；错字“微新/文件传书助手”和同聊天“还是刚才那个”检查上下文理解。重试只核对前次结果，已发送的不应重发。未实现跨次任务的严格发送去重。

### M2.5 悬浮监控及浏览器读取（版本 196）

用户在版本 195 操作默认浏览器查询资料后失败。系统默认浏览器角色核对为 `com.heytap.browser`。用户自行展开本轮 `phone_*_observe`，只读截图 72 确认真实返回 `accepted=false`、`code=STALE_WINDOW`、`detail=窗口或执行许可已改变，请重新观察。`；此前 70、71 只有模型解释，不作为真实工具结果。即时无障碍检查为绑定且无崩溃，未据此推断 Root 或无障碍授权丢失。

旧版该错误对应树读取被中止，可由内容 revision 或执行许可改变触发；没有更细事件轨迹，不能唯一断言此次必定由页面刷新造成。代码修复同窗口内容变化立即中止且没有重读的路径：只读观察最多 4 次／4.5 秒，仍不稳定报告 `PAGE_UNSTABLE`。切窗（包括延迟到达的往返切窗事件）、STOP、锁屏、断连不能作为内容刷新继续重试。动作无自动重放。
