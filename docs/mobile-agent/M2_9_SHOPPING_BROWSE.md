# M2.9：有界翻页、商品预筛与评价证据

更新：2026-09-28。范围仍为 V1。此文记录开发检查点及 200 真机证据，不代表京东或其他平台业务验收完成。

## 目标与验收口径

用户本轮优先要求自主翻页、对比最优商品，并补充不能把可能刷单形成的高分直接当作优质商品。

首轮目标为京东：由 App 的模型在真实任务中翻页，收集至少三个不同且规格、数量可比的候选；分别列展示价、待核费用、优惠条件与评价证据，说明推荐依据。找不到足够证据时报告不足，不以排序第一或动作被接受代替任务完成。美团、淘宝、拼多多的业务验收仍待后续进行。

## 实现内容

### 页面缺口与滚动能力分开

199 的真实诊断已确认京东结果页可以在窗口、revision 稳定时仍缺少子节点；根本原因尚未确认。

200 增加严格的 `scrollOnly` 能力：仅在有限重读的最后一次确实完成、仍处同一有效窗口、唯一问题为 `unavailable_child`、已读部分未发现敏感内容且存在合格原生滚动节点时返回。仍保留 `truncated=true`，不宣称页面完整。

- 对外只给可滚动节点，清空商品正文和点击、输入能力。
- 执行前重新读取、核对内部快照与窗口，并重新解析目标及祖先。只派发节点明确提供的原生滚动动作。
- 不调用 Root 或坐标滑动后备；原生滚动拒绝不会重复派发。
- 不允许点击、输入、返回、截图或重新打开应用来绕过限制。
- 同任务受限滚动最多五次；暂停恢复不刷新此预算。原有连续三次未见变化暂停、单次快照、十秒时效、STOP 和锁屏约束继续有效。
- 不完整页面不会进入购物或评价证据。到达完整页面以后才恢复正常操作与证据采集。

这项策略用于继续浏览并寻找可完整读取的页面，不能证明缺失部分无害，也不能保证当前京东页面一定提供可用滚动节点。节点缺口混入时间、数量、文本、外来包名等其他问题时继续拒绝。

### 跨页商品预筛

- 当前授权内保留最多 32 次完整观察、总计最多 256,000 个文本字符；按整份观察淘汰。此预算是字符数，不是序列化字节数。
- 证据保留不延长动作快照的有效期，暂停和 STOP 仍清空证据。
- 费用不完整时按已见单价乘数量提供展示小计预筛，单独标记 `is_payable=false`、`is_final_best=false` 和待核条件。
- 运费、其他费用、券资格缺失时不补零、不猜测；原有严格计算条件保留。
- 同一组商品身份、规格、价格节点重复提交会被拒绝，改候选编号或摘录不能增加候选数。
- 跨观察同标题同规格只标疑似重复，不合并、不据条数宣布已经确认多个独立 SKU。

**当前还没有宿主核证的商品卡片／SKU 归属。** 工具明确输出 `product_binding_verified=false`；真实引用只能证明文字确实出现，尚不能证明来自不同节点的标题、价格、店铺与优惠属于同一商品。因此排序和金额计算仍需核对，不能作为最终最优商品的完整验收。

### 评价证据与异常线索

新增本地只读工具 `shopping_review_evidence`，只分析当前授权内真实观察的引用。要求分别采集中差评、追评、具体使用体验，结合重复文案线索判断证据是否充分。

- 不凭高分、销量、广告位或商家宣传认定质量好。
- 同一来源节点的多个摘录不会算成多条独立评论；独立评论数和商品归属未核证时明确保留未知。
- 长文本重复或高相似只形成待核异常线索；通用短句不直接触发刷单判断。
- 不输出刷单概率、确定鉴伪结论或凭这些线索产生质量排名。
- 样本不足、缺中差评或追评时明确说明；页面评论的内容仍是待核数据。

### 同源只读诊断对照

debug instrumentation 增加默认配置、包含非重要节点、逐父节点刷新及两者结合四组实验。每组统一 768 节点／2 秒预算，生产默认仍为 512 节点。实验临时配置按原服务、任务和诊断句柄绑定并清理恢复，不发布可执行观察，不执行滚动或其他动作。

诊断读取成功、完整生产观察、受限滚动可用和购物业务成功分别记录。不能把实验节点增加或缺口减少记为修复完成。

本次同源对照中，包含非重要节点的配置能读到更多结构，但仍缺一个子节点：父路径 `/0/0/0/1/0/0/4/0/0`，`LinearLayout`，父 bounds `[0,603,1080,604]`，声明 4 个子节点、索引 1 不可读取。1 像素高的是父容器，不能当作缺失子节点的边界或据此认定无害。563 个已访问节点也超过生产默认 512 节点预算；该配置尚未改为生产默认。当前证据不能解释底层为何返回空子节点，也不能建立可信商品卡片或 SKU 归属。

### 原生滚动首轮未进入动作阶段

`jd-native-scroll-200-a.json` 与 `.log` 记录前置 `before_observe` Activity 检查返回 `ACTIVITY_CHECK_EXCEPTION`，耗时约 15.2 秒。`actionRequestsIssued=0`、`controllerActionsUsed=0`；`selectedNode`、`before`、`after`、`accepted`、`screenChanged` 均为 `null`。测试自己的会话随后停止清理。

因此这是测试前置 Activity 检查异常，未执行观察或滚动请求，既不是 APP 原生滚动失败，也不是滚动成功。`engineeringScrollPassed=false`、`businessTaskAccepted=false`；runner 的 `OK (1 test)` 不能覆盖这两个实际结果。后续需修正前置检查并重测。

### 后续 201 开发状态

201 的独立 DEBUG 结构采集入口正在开发，拟保留真实父路径、卡片层级和缺口，仅输出无正文元数据到本地受控产物；生产诊断的正文禁入规则保持不变。截至本次文档更新尚未验证，不能记为 201 构建、安装、测试或商品归属验证通过，也不计入 200 的 362 项回归。它不赋予新的点击或购物权限。

## 仍需解决与下一步

1. 修正原生滚动测试的前置 Activity 检查并重测，分别核对动作是否派发、是否接受及页面是否变化；已有四组同源对照仍未得到完整页面。
2. 验证后续独立结构采样入口，再对真实京东页面建立宿主可核证的单商品卡片、SKU／商家归属；解决跨节点混拼及可靠去重。结构采样成功不能替代商品证据验证。
3. 用 App 自身模型完成翻页、至少三个可比候选、评价抽样、明确待核费用的流程，保留实际成功和失败证据。
4. 再验普通免费券的规则、领取、应用与最终金额核对；不自动下单、付款或消耗积分、储值、会员权益。
5. 京东流程达到验收标准后扩展美团等平台和非 Root 设备。
