# V1 第二里程碑设计备忘

此处 M2 指 V1 的第二个里程碑，**不是 V2**。以下仍是待实现设计；先完成 M1 的 APK 构建和基本验证。

目标闭环：在指定聊天内显式开启手机控制 → 观察获准目标应用 → 执行节点动作 → 验证结果 → 暂停或停止。

## 集成边界

- `AgentSessionManager`：仅内存中的单个控制会话，绑定 conversationId、assistantId、sessionId、epoch 和获准目标包。只有用户可开启、恢复；STOP 同步撤销执行许可。
- `PhoneController`：串行处理观察与类型化动作。每次执行时复核会话、目标包、锁屏、预算、节点快照及付款保护。
- `MobileAgentAccessibilityService`：用户从系统设置显式授权后连接；没有已开启会话时不采集界面。服务断开使会话及句柄失效。
- `UiTreeCompressor`：过滤空容器并继续遍历其子节点；隐藏密码字段，限制深度、数量、文本和总输出。重复名称的两个按钮不能简单合并。
- `AccessibilityPhoneBackend`：操作新鲜节点，返回系统是否接受、页面是否改变、是否仍在目标应用；不能将一次 API 返回 true 等同任务成功。
- `PhoneTools`：只加入获准聊天。模型不能创建或恢复手机控制会话；工具参数不能充当用户审批凭据。

第一批动作：打开目标应用、读取前台状态和压缩树、节点点击、文本输入、滚动和返回。坐标点击、Root 动作及截图后续逐步接入，避免绕过节点保护。

## 必须在执行时检查

每次调用绑定 `conversationId + sessionId + epoch + snapshotId`。STOP、新会话、进程重启、服务断开、窗口变化均不能使旧节点或审批复活。前台不是获准应用时进入 `WAITING_FOR_FOREGROUND`，不得读取其他应用内容或点击。

用户开启会话时说明：获准应用的可见内容可能交给当前配置的模型服务处理。系统无障碍权限不等于已同意每个聊天读取手机。

付款、支付密码、生物识别和支付验证码必须停在用户接手状态，即使普通工具审批已通过也不能绕过。对于含糊目标，重新观察或暂停。

## 现有代码的接入注意点

1. `ChatToolFactory.createTools()` 需要聊天上下文，普通聊天不自动获取 Phone Tools。
2. `GenerationLoop` 在审批恢复后直接调用工具，手机策略不能只放在 `needsApproval` 中。真实执行上下文由编排层传入，旧工具行为保持兼容。
3. `GenerationLoop` 现有完整工具参数日志需对手机工具去掉输入原文。
4. `ChatNotificationManager` 当前在通知中显示 `lastTool.input.take(100)`，手机工具不得沿用。
5. 聊天通知持续更新同一前台通知 ID。Agent 使用独立通知及易触达 STOP，避免停止按钮被下一次通知覆盖。
6. `ChatService.stopGeneration()` 应先撤销手机执行许可，再取消生成；每个新动作派发前再次检查 epoch。已经完成的点击无法撤销。

## 验证

覆盖未授权聊天、过期审批、服务断开、前台切换、锁屏、过期节点、重复标签、敏感字段、输出截断、STOP 竞争和相同动作三次无变化暂停。真机先执行系统设置内无风险页面的观察、滚动、返回，再测试专用输入框。

同一应用内人工触摸与自动操作仍存在竞态；不得宣称能够识别所有人工操作或任何情况下都不会冲突。
