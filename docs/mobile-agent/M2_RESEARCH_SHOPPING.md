## 本轮入口和职责

| 入口 | 当前实现 | 不代表什么 |
| --- | --- | --- |
| `read_public_webpage` | 直接读取公开 HTML/纯文本，在本地提取正文、来源信息和链接，并保存有界缓存 | 不操作浏览器，不取得手机控制授权，不下载 PDF/安装包/压缩包 |
| `read_research_source` | 按本聊天的 `source_id` 从本地缓存分段复读 | 不联网，不允许引用其他聊天的来源 ID |
| `shopping_compare` | 对本次手机实际观察证据做本地金额计算、优惠组合和同规格候选排序 | 不自动领取、选券、下单、付款，也不增加执行权限 |
| 手机动作与 PaymentGuard | 使用当前授权的手机工具逐步操作；下单、付款、会员和账户资产动作由本地规则拦截 | 工具或模型声称“已授权”不能越过拦截 |
| Root 使用选择 | 复用近期真实验证，或对本机曾明确验证成功的权限进行短时复核 | 不把“曾验证”当成永久 Root 授权，不向模型开放任意 shell |

公开研究工具沿用助手的联网搜索开关及聊天上下文。购物工具只随本次有效手机授权注入，普通聊天或旧工具历史不会取得新的手机执行权。

## 公开网页研究

流程为：从用户给出的链接或实际搜索结果取得候选 URL，读取正文，再依据实际返回的来源信息组织结论。已有 `search_web` 的配置和搜索能力保持原样；正文读取失败时不能把搜索摘要当作已经读取的原文。

正文提取优先选择文章、主内容、README 等区域，移除脚本、常见导航、表单和候选广告区块。它是 HTML 结构启发式处理：移除区块数不是准确广告条数，也不保证动态页面、复杂排版或正文完整可读。结果中的 `limitations`、`truncated` 和 `returnedTextTruncated` 需要保留和解释。

来源记录包括请求 URL、最终 URL、标题、抓取时间、网页自报发布日期、MIME、提取方式、正文 SHA-256、相关链接和提取限制。抓取时间不等于发布日期；网页自报日期没有被独立认证。SHA-256 对应**完整本地留存的 UTF-8 正文**，不是原始网页文件、下载文件或单次返回片段的哈希。

网络和资源限制：

- 仅公开 HTTP/HTTPS、默认端口 80/443；拒绝 URL 用户名/密码、本机、内网和其他非公开地址。域名解析结果及每次重定向重新检查；HTTPS 不降级到 HTTP。
- 独立 HTTP 客户端不继承模型 API 认证头，不使用登录 Cookie、不运行 JavaScript，不绕过登录、付费、验证码或站点访问限制。当前客户端直接连接，不继承应用 API 代理；依赖代理的网站可能无法读取。
- 单页响应最多 1 MiB，限制包含解压后的正文流；总读取最多 15 秒，最多三次重定向。取消会取消相应 HTTP 请求。
- 本地留存正文最多 24,000 字符；单次默认返回 12,000，`max_chars` 范围为 1,000–18,000。可用 `nextOffset` 经缓存工具读取剩余留存正文，无需重新下载。
- 最多两个并发读取；应用私有来源缓存最多 64 份、总计 8 MiB、保留七天，单份缓存上限 256 KiB。缓存 ID 绑定聊天，并在复读时校验正文哈希。该缓存是有界研究缓存，不是永久归档或通用下载目录。

实际网页读取会访问目标站点。工具返回的正文会进入当前模型上下文，可能由用户所配置的模型 API 处理；“本地提取”不意味着正文永远不会进入模型请求。来源页面及其中的指令只是待分析数据，不能扩大用户授权。

链接被标记为 `pdf`、`document` 或 `github`，仅表示链接类型提示。必须区分“发现链接”“读取正文”和“下载并校验文件”，本轮没有把这三者合并成完成状态。

## 当前购物范围

采用通用商品/外卖数据结构，能够表达淘宝、京东、拼多多、美团页面可见的商品价、配送费、包装费/服务费、评分及普通优惠券。这里的“支持”是通用证据和计算能力，不是四个平台的私有接口或逐页适配完成证明。

**当前一次手机授权仍只绑定一个目标应用。实际落地范围是单平台、同一授权内的多个商品比较。** 不能一次授权便跨淘宝、京东、拼多多和美团搜集、领取或执行，也没有跨授权自动汇总购物证据。切换目标需要新的本地授权，原证据不会自动继承。

候选按页面提取的商品身份、规格和数量分组：品牌、型号/版本、容量/分量、套餐内容等不一致时，不能因为金额更小就判定更便宜。没有多件数量证据时只按单件比较。食品口味、分量和套餐内容不一致，也不能混为同规格候选。

购物证据来自 Controller 的真实观察记录：

- 每份证据携带 `snapshotId`、目标包名及节点 ID、文本、描述。宿主按当前完整 token（聊天、助手、session、epoch）提供证据，工具参数不能自行提供“已核验”或“已授权”标记。
- 最多保留八个快照、总文本不超过 64,000 字符；暂停、停止、新会话撤销旧证据。模型只能引用本次实际记录中存在的 `snapshot_id`、`node_id` 和原文 `quote`。
- 字段值和金额要能追溯到引用原文。旧快照、伪造引用或计算期间已经撤销的证据会被拒绝。
- 引用匹配证明字段来自本次读取记录，不等于平台已保证库存、账户资格、商品真伪或最终结算价格；关键条件仍需在实际页面复核。

### 本地 DiscountEngine

输入金额为最多两位小数的人民币十进制字符串，计算及输出使用整数分，不使用浮点价格运算。单次上限为 12 个候选、12 张券，有界枚举可用组合。

当前支持固定商品金额减免和固定配送金额减免。商品满减门槛只计明确的商品原小计，不用运费、包装费等凑门槛。运费和其他必付费用要分别核实；没有看到费用不等于零。价格若已含券、仅是起价/预估价，或无法确认优惠前口径，不重复减券，也不输出确定实付。

券的适用商品、账号资格、生效/失效时间、取得方式及叠加关系必须明确。互斥组不可组合；不同组也不默认可叠加。每一对券需要明确可叠加证据，未知关系只分开模拟。配送券最多减配送费，商品券最多减商品小计，不把减免余额继续抵扣其他费用。

结果区分：

- `confirmed_plan`：基于已知费用和当前已具备、可用优惠的最低可确认实付。
- `after_free_claim_plan`：普通免费券领取成功后可能获得的更低方案；仍须实际领取成功、选券并在结算页核对，不能当作已到手优惠。
- `coupon_decisions` 和 `unknowns`：逐券列出排除原因及缺少的条件；候选无法定价时不进入最低可确认结果。

结论仅限当前已经观察且具有可比性的候选，不是全平台、全网或隐藏优惠的最优保证。评分、评价数量和质量原文分别展示，销量不能代替评价数量，“1万+”不伪造为精确数量。评分高或页面宣传均不能证明质量最好。

本轮未支持百分比折扣、满件、阶梯折扣、折后门槛或复杂结算顺序的自动求解。这些情况需要作为未知规则报告，不能强行套用固定金额模型。

### 普通免费券与交易边界

用户本次允许领取普通免费券时，可由当前授权的手机工具逐步领取和应用，每步重新观察确认。`shopping_compare` 本身完全没有设备副作用，不会领取、选券或提交订单。

会员、订阅、自动续费、免费试用、绑定服务及消耗积分/储值不属于普通免费领券。不能为降低报价自行触发这些操作。最终下单、付款、支付密码、支付验证码、生物识别认证等由用户处理。

交易节点判断读取完整的有界文本后再裁剪预览，并覆盖受限标签的可操作祖先和后代，防止通过无标签包装按钮绕过。付款规则是本地保守防线，不是对所有平台页面和所有措辞识别无误的保证；真实页面仍需专门验收。

## 页面裁剪与完整检查

本轮区分“输出预览被裁剪”与“安全遍历没有完成”：

- 预览最多输出 100 个节点和 12,000 个文本字符；输出达到上限后仍继续有界安全遍历。单字段预览截短不等于该字段没有检查。
- 访问量、深度、总时间、子节点数、超长字段、外包节点或无法取得的子节点等造成检查缺口时，记录实际不完整原因。真实检查不完整的页面仍禁止动作及截图。
- 完整检查后允许的普通页面导航，不因此开放最终支付；被识别为密码、验证码或其他敏感内容的页面仍按原有规则交给用户处理。

购物证据只含受限的观察输出，不包含未读取的原生页面全文；不能把被裁剪的内容补写成已观察事实。

## Root 验证与升级迁移

新版把“使用 Root 的偏好”“本机曾验证成功的历史”和“当前真实 Root 能力”分开保存/判断。偏好和验证历史写入应用的 `noBackupFilesDir`，不通过 Android 备份迁移到另一手机；当前 UID 0 授权和最近成功检查时间不被持久化为永久许可。

初次安装或从没有该本地历史记录的旧版本升级，即使 Root 管理器曾允许本应用，也不会仅凭设备型号、管理器存在或旧界面截图认定已验证。需要用户明确执行一次验证。打开 Root 偏好开关或进入能力页，不等于发起新的 Root 授权请求。

用户验证成功后，在启用 Root 的前提下，任务开始/恢复可以复用 60 秒内的真实成功检查；超出窗口或重启进程后，只有本机已有成功历史且允许自动复核时，才进行最多约 1.5 秒的短时只读复核。被动刷新不运行 Root 探测。

复核拒绝、失败、取消，或实际 Root 命令不可用后，会停用自动 Root 重试，等待用户重新明确验证。新任务可使用可用的无障碍路径；结果不确定的已尝试 Root 动作必须重新观察，不能把“未确认成功”当作“没有执行”再重复提交。

Root 仍只提供受限输入能力。模型不获得任意 shell、Root 管理器控制或全局权限配置能力。此迁移策略的真机验证需包含升级保留数据、进程重启、关闭偏好、撤权/拒绝和恢复，不可仅凭一次 UID 0 检查宣布通过。
