## 208 实现与范围

- **启动准备仅检查就绪元数据。** 宿主专用 `openForTaskPreparation` 保留原 token、授权、前台及动作预算检查，仅请求打开目标应用，再确认服务连接、未锁屏、目标包与窗口就绪；不在此阶段 capture 页面树，不生成动作快照或购物证据。模型自己的 `open_app` 和后续 `observe` 仍按完整读取及授权规则执行，准备成功不授予旧节点动作权限。
- **保留启动原因。** 准备失败先记录对应原因；后续会话到期仍显示此前启动失败信息，避免只剩时间上限。它不自动恢复授权或重发模型请求。
- **极窄的 Root 优先翻页。** 新路径仅适用于已授权且 Root 当前可用的京东完整安全页面；全树不得有交易限制、敏感或缺失内容。必须是宿主可验证的明确竖向主体滚动节点，并依据节点与窗口的交集生成内部手势，不接受模型自报坐标。
- **派发前仍需一致。** 同时检查单调时钟与墙上时钟的原有 10 秒时限、原 token／窗口身份／窗口 revision、严格祖先、节点签名、全树 fingerprint 和上层窗口遮挡；路径受限或证据不足就不选新 Root 优先路由。Root 在派发前及执行期间继续检查授权与窗口状态。
- **选中 Root 后不重复执行。** 只有未选择新 Root 路径才进入普通路由；一旦选择，返回 false、未知结果、异常或取消均不再用原生动作重发。旧的“原生明确拒绝后再按既有条件尝试 Root”后备机制仍存在，不能将本次京东竖向节点优先策略写成所有旧 Root 后备动作的统一范围。
- **标明执行器来源。** 结果及回执可携带 `root_input`／`accessibility` 枚举，表明哪个执行器返回结果，便于区分实际路线；该字段自身不证明已派发、画面已变化或业务完成。既有 Root 授权偏好与实时重查继续复用，不新增持久 shell 或永久授权承诺。

## 208 两轮模型实测

证据仅留项目根 `artifacts/v1-m2.17-root-scroll/model-run-1/` 和 `model-run-2/`，不公开随机调用／快照标识、推荐词、坐标或设备正文。两轮使用上述最终 208 源码与 APK，不覆盖先前失败记录。

- **第一轮：已送达模型，但未取得手机动作证据。** 聊天出现宿主续跑的实际消息，模型正常完成回复，界面显示思考 4.1 秒；这是界面思考统计，不是独立测得的整项任务耗时。模型自述只有提议／网页工具，未见后续 phone 工具调用；这段自述不能证明实际请求 schema 缺少手机工具。静态参数传递检查也未发现明确漏传点。
- **第二轮：确认手机工具可用。** 同配置下，用未写内部工具名的普通用户语句开始新任务，实际出现 `observe`／`click`。最后卡片明确显示“本轮模型执行已结束，手机控制授权已撤销”；主线没有 STOP，也没有操作京东。该轮证据确认启动送模型及手机工具执行链已有进展，不能将第一轮模型自述写成已证实的工具缺失故障。
- **点击仍因 revision 变化被拒绝。** `second-click-detail.txt` 与 `last-click-detail.txt` 均为同一推荐词入口的 `accepted=false`／`STALE_SNAPSHOT`，`reason=REVISION_CHANGED`；对应快照年龄分别为 1,089 ms、1,396 ms，`window_changed=false`。本轮已直接核对该拒绝原因；不能把它反推为 206 或 207 旧记录的确定原因。
- **选择的仍是当前未支持重验证的入口。** `second-observe-full.txt` 为 85 节点的完整观察，`truncated=false`、`previewTruncated=false`、`scrollOnly=false`，没有检查缺口；可见明确的搜索栏上下文和独立搜索按钮。模型实际选择的是搜索栏内唯一推荐词入口，没有选择 207 已支持的明确“搜索”按钮，因此本轮没有验收后者的重验证路径。

搜索尚未成功，没有三候选或 Root 翻页业务通过证据。下一版 209 正单独开发 `JD_SEARCH_ENTRY` 窄范围证明，研究在同一入口上下文下容许推荐词及右边界变化；这不属于 208 已实现或通过的能力。
