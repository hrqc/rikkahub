# V1 M2.8：动态页面诊断与失败暂停

日期：2026-09-27。版本 199，`2.5.4-mobile-agent-v1-m2.8-dynamic-ui-diagnostics`。这是专项 D1 的内部检查点，不是京东购物或 V1 完整验收。

## 已完成的修改

- 审查并完善用户提供的专项方案，保留下载原稿。执行依据见 [DYNAMIC_UI_SPRINT.md](DYNAMIC_UI_SPRINT.md)。
- 在生产 TreeReader / Backend 原路径添加默认关闭的诊断，记录结构缺口、真实读取耗时、窗口身份、事件类型、根节点刷新和缓存清理结果；不导出页面正文、输入值、通知正文或截图。
- 显式测试才能启用，绑定当前有效授权；暂停、STOP、锁屏、窗口身份变化或撤销后停止记录，旧 token 不能重新开启。内存记录最长 15 秒，7 个样本、32 次尝试、128 个事件，单次最多 20 条缺口。后端 112 KiB，全部导出含外围记录和换行不超过 128 KiB，取走后清空。
- 最终 `PAGE_UNSTABLE` / `INCOMPLETE_SCREEN` 明确暂停；真实不完整页面不发布快照或购物证据。仅预览文本裁剪不误判为整树不完整。
- 手机工具中断时明确“执行结果未知，先重新观察，不得直接重放”，不再自动推断动作未发生。普通工具保留原行为。
- 提供仅在已选前台页面进行读取的 instrumentation 入口、本地 JSONL 解码器，以及独立 USB 驱动的 flags / 子节点查询对照参数。生产读取 flags、遍历预算和动作放行规则未放宽。

## 当前问题与下一步

生产结果页四次同窗口／同 revision 读取均为 55 个已访问节点、同一父容器六个空子节点；刷新和清理缓存没有恢复。父容器覆盖屏幕，不能证明缺口无害。辅助 flags 对照改变了节点数量，但没有稳定消除缺口，且其 563 节点超过生产预算。细节见 [根因调查记录](DYNAMIC_UI_ROOT_CAUSE_REPORT.md)。

下一步在同源诊断中控制变量复核节点过滤／预取与残余缺口，随后才修改生产策略并验证搜索、滚动、再读取及三个同规格候选。平台验证恢复、真实券领取与应用、模型超时真机注入、截图偶发失败和 OPPO 非 Root 仍待验收。V2 继续关闭。
