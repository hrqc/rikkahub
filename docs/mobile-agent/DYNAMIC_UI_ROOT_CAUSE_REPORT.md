### 结果页第二轮确认的缺口

四次读取的 `windowId`、`identity`、`revision` 在每次前后及各次之间均保持一致；四次结构摘要也一致。每次只有 `unavailable_child` 这一检查问题，均为 `truncated=true`、`sensitive=false`。没有达到节点数、深度、文本等其他检查上限的记录；未检测到敏感节点不等于未取得的子树已经安全。

| 字段 | 四次一致的结果 |
| --- | --- |
| 缺口父路径 | `/2/0` |
| 父节点类型 | `android.view.ViewGroup` |
| 父资源 ID | `com.jd.lib.search.feature:id/ys` |
| 父边界 | `[0, 0, 1080, 2328]`，覆盖当前应用的可视屏幕区域 |
| 父节点可见性 | `parentVisible=true` |
| 声明子节点数 | `childCount=8` |
| 取不到的子节点索引 | `1、2、3、5、6、7` |
| 实际访问 / 可见 / 输出节点数 | `55 / 47 / 44` |
| Root 节点 refresh | 四次均返回成功；这里的 Root 指页面树根节点，不是设备超级用户权限 |
| 目标子树缓存清理 | 四次均返回成功；随后尝试仍得到相同缺口 |

四次读取耗时分别为 143、193、192、167 毫秒，本次观察总耗时约 1,079 毫秒。失败发生在四次尝试耗尽后，并不是耗满 4.5 秒时间预算。该证据只证明缺口在这段观测期间持续存在，不证明长期永久存在。

因此，这一轮失败不能仅归结为“窗口一直切换”“revision 一直变化”或“根节点 refresh 返回失败”。现有刷新和缓存清理在本轮没有恢复缺失子节点，但仍不能据此确定是京东节点提供方式、系统缓存或其他底层因素造成。

**父容器覆盖可视屏幕，六个空子节点自身没有可核对的边界。不能把这些缺口认定为屏外、装饰节点或无害节点，也不能由剩余 55 个已访问节点推导商品区域全部完整。** `totalNodeCountKnown=false`，55 是实际访问量，不是页面真实总节点数。相同结构摘要只证明已记录结构相同，不证明缺失部分完整或可以放行动作。

### 采样入口问题与页面失败分开统计

在上述生产采样前，`jd-home-production-1` 因 JUnit 方法返回类型不符合 void 要求而初始化失败；`jd-home-production-2` 因服务重连后前台包名元数据仍为 null 而在采样前断言失败。随后分别修复显式 `Unit` 返回和等待已选目标窗口元数据就绪，再取得 `jd-home-production-3` 及结果页两轮证据。

这两次是测试入口／环境就绪问题，没有形成可用于判断页面读取的观察样本，不能混入京东页面失败次数，也不能算成页面读取通过。原失败日志保留在本地，未以修复后的结果覆盖。

## 本轮已从代码确认的问题

- 控制器原来的暂停集合未包含最终 `PAGE_UNSTABLE` 和 `INCOMPLETE_SCREEN`。工具失败不能等同于会话已经 PAUSED。本批补明确暂停，不放宽页面检查。
- 暂停可能在工具结果写入聊天前取消生成。原有统一中断文案可能让模型误以为动作未完成且由用户取消。本批对未完成手机工具明确记录结果未知、必须重新观察、不得直接重放。

以上两个问题可以通过代码和回归核验，但不是京东空子节点的已确认根因。

## 本批诊断策略

为生产 `AccessibilityTreeReader` / `AccessibilityPhoneBackend` 增加可选、限时、限量、无正文元数据记录。用明确启用的 debug instrumentation 在已经处于前台的目标页只读采样，保留原授权、窗口、敏感性与 STOP 检查。

JSONL 区分诊断采集是否完成、观察是否成功、会话是否暂停。JUnit 采集用例完成不等于该页面读取成功，更不等于商品比较通过。密集计划时隙可能跳过，必须使用实际时间解释。

本批不开放 `PARTIAL_BUT_ACTIONABLE`，不增加无限重试，不自动恢复失败会话，不绕过平台验证。
